Reactor：先看信号，再看数据

一次订阅中的四类信号与核心接口。

协议角色

  • Publisher<T>：向订阅者提供数据序列；Reactor 的 Mono/Flux 是 Publisher。
  • Subscriber<T>：接收 onSubscribe、onNext、onError 或 onComplete。
  • Subscription：Subscriber 通过它向上游 request(n) 或 cancel()。

信号路径

subscribe(): 订阅关系建立（onSubscribe）
request(n): 需求沿链向上游传播
onNext(value): 数据沿链向下游传播
onComplete() / onError(error): 终止信号
cancel(): 取消后不再需要后续信号

记忆句：数据向下游走，需求向上游走；取消表达不再需要。request(n) 不是线程切换指令。

心智模型

多数 cold publisher 会在每次订阅时重新执行其源；但不要把“订阅前绝无动作”当作所有 publisher 的普遍规则。比如 just(value) 在组装时捕获 value，hot publisher 也可独立于订阅者发出信号。
